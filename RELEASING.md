# Releasing

Releases are automated with [release-plz](https://release-plz.dev) using a Release PR flow.

## Flow

1. Changes are merged to `main`. CI runs, nothing is published.
2. The `Release` workflow opens or updates a Release PR that bumps the version, updates `CHANGELOG.md` and `Cargo.lock`.
3. Review the Release PR. Edit the version or the changelog in the PR if needed.
4. Merge the Release PR when a release is wanted. The `Release` workflow then validates the workspace (`mise run test`, `mise run package`), publishes every crate whose version changed to crates.io, and creates the tags and the GitHub release.

Ordinary merges never publish: `release_always = false` restricts publishing to merged Release PRs. If validation fails, nothing is published.

## Workspace

The repository is a Cargo workspace of two crates, released on their own: `sane-sys` (raw bindings) and `libsane` (safe API). Each has its own version, tag (`<crate>-vX.Y.Z`), GitHub release and changelog (`<crate>/CHANGELOG.md`).

New crates start at `0.1.0` and are published as is by their first Release PR. Crates are published in dependency order, so `sane-sys` goes first.

Publishing builds each crate from its package, and `sane-sys` needs libsane: the release jobs install the system packages of `mise.toml` (`mise bootstrap packages apply`).

## SemVer policy

Pull requests are squash-merged, so each pull request title becomes one commit on `main`. The `PR Title` workflow requires titles to follow [Conventional Commits](https://www.conventionalcommits.org) (`feat: ...`, `fix: ...`, `feat!: ...`). Merge commits and release commits are left out of the changelog.

The proposed bump is derived from these commits since the last release:

| Commit | `>= 1.0.0` | `0.x.y` |
| --- | --- | --- |
| `fix:` and other types | patch | patch |
| `feat:` | minor | patch |
| `feat!:`, `fix!:` or `BREAKING CHANGE:` footer | major | minor |

The maintainer has the final say and may change the version in the Release PR.

[cargo-semver-checks](https://github.com/obi1kenobi/cargo-semver-checks) runs on the Release PR and reports public API breaking changes in the PR body. If it detects a breaking change, the bump is raised accordingly.

## Changelog

Changelogs are generated by release-plz with git-cliff using the `[changelog]` section of `release-plz.toml`, and the entry for the release is used as the Release PR content and the GitHub release body.

## Required setup

- Repository secret `CARGO_REGISTRY_TOKEN`: a crates.io API token with the `publish-new` and `publish-update` scopes.
- Settings > Actions > General > Workflow permissions: enable "Allow GitHub Actions to create and approve pull requests". Optionally, set the repository secret `RELEASE_PLZ_TOKEN` to a personal access token: the `release-plz-pr` job uses it instead of `GITHUB_TOKEN`, which also lets CI run on the Release PR (pull requests opened with `GITHUB_TOKEN` do not trigger other workflows).
- Repository secret `CODECOV_TOKEN` for the `Coverage` workflow.

```sh
gh secret set CARGO_REGISTRY_TOKEN
gh secret set CODECOV_TOKEN
gh api -X PUT repos/AlixANNERAUD/libsane_rust/actions/permissions/workflow \
  -f default_workflow_permissions=read -F can_approve_pull_request_reviews=true
```
